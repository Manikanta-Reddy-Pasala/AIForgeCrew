# ADK 2.0.0b1 Migration Implementation Plan

> **Status (2026-05-04):** Tasks 1–5, 7–9, 11 executed locally; Tasks 6 + 10 deferred to NUC deployment (need live Postgres). Step-level checkboxes throughout the plan reflect the original spec — see commit history for evidence of completion.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bump `google-adk` from 1.31.1 → 2.0.0b1 across the whole tree (sidecar + main runtime), reset the Postgres `adk_sessions` schema, delete the now-redundant sidecar, and confirm the 5-agent SequentialAgent + LoopAgent workflow still runs end-to-end.

**Architecture:** ADK 2.0.0b1 is API-compatible with 1.31.1 at the import surface — `BaseAgent`, `LoopAgent`, `SequentialAgent`, `InvocationContext`, `Event`, `EventActions`, `BasePlugin`, `Runner`, `DatabaseSessionService`, `InMemorySessionService` all still resolve. End-to-end smoke test proved a `Runner(app_name=..., agent=SequentialAgent(...), session_service=..., plugins=..., auto_create_session=True)` constructed from `BaseAgent` subclasses runs `run_async(...)` cleanly. Migration is therefore primarily: (1) flip pin, (2) reinstall, (3) reset session DB schema (per upstream README), (4) smoke. No code rewrite of the workflow / agent classes is required.

**Tech Stack:** Python ≥3.11 · `google-adk==2.0.0b1` (replaces 1.31.1) · Pydantic v2 · Postgres (aiforge DSN) · SQLAlchemy + asyncpg (transitive via google-adk) · pytest.

**Locked decisions (per Manikanta, 2026-05-04):**
- Sidecar dir `scripts/runtime/adk2-sidecar/` deleted (workflow.py learnings already absorbed into main runtime).
- Postgres `adk_sessions` / related tables wiped + recreated (dev infra, no in-flight prod tickets to preserve).
- `legacy/` folder kept for now — out of scope for this PR.
- `ask_user` → `RequestInput` HITL migration kept as a follow-up ticket (out of scope here).
- Single-PR delivery, multiple commits, no feature flag.

- [ ] **Step 2: Write the migration SQL**

Use Write tool to create `scripts/migrations/2026-05-04-adk2-sessions-reset.sql` with the following content (substitute the actual table names you captured in step 1 if they differ):

```sql
-- ADK 2.0.0b1 migration — reset session storage.
-- Rationale: 2.0.0b1 changed the SQLAlchemy schema (sessions/schemas/v0,v1).
-- We accept data loss because (a) sessions are scratch state, (b) tickets
-- live in `tickets`/`ticket_events` (untouched here), (c) no in-flight runs.

BEGIN;

DROP TABLE IF EXISTS events CASCADE;
DROP TABLE IF EXISTS sessions CASCADE;
DROP TABLE IF EXISTS app_states CASCADE;
DROP TABLE IF EXISTS user_states CASCADE;
DROP TABLE IF EXISTS app_user_states CASCADE;

-- ADK 2.0b1 will auto-create its own tables on the next
-- DatabaseSessionService(db_url=...) instantiation. No CREATE TABLE here.

COMMIT;
```

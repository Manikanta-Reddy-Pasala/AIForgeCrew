AIForge · scoped OKR memory

How the memory works

A plain-markdown, goal-shaped memory. Every durable fact is written into one OKR brief, sorted into a scope, folded by an LLM, and read back as a compact briefing. This is the write path, the compaction path, the links, and the read path — end to end.

write direction compaction read / recall global project topic

01Two layers, one truth

The markdown briefs are the human-facing source of truth; the search backend is a mirror.

Markdown OKR briefs source of truth
Plain .md files under ~/.aiforge/memory/. You can cat them, diff them in git, hand-edit them. One brief per scope.
Search index mirror
Embedded SQLite — vectors + full-text for ranked recall. Every write is mirrored here. Regenerable; the md briefs are authoritative.

Rule of thumb: if it isn't stamped into a brief's frontmatter (repo / topic), it won't roll up into that scope.

02The OKR envelope

One Google-OKR shape for every brief — Objective + measurable Key Results, plus three upkeep sections. Nothing deviates from this; only how it's filled changes.

---                              # frontmatter = machine identity
kind: knowledge
key:  oneshell-pos               # the scope
updated_at: 2026-07-12T09:00:00Z
tags:  [repo:oneshell-pos, topic:data-sync]
links: ["[global](compacted-shared.md)"]   # cross-scope map
---
# oneshell-pos brief

## Objective     the durable intent for this scope
## Key Results   measurable outcomes · TICKETS worked live here
## Facts         points to remember — config, current state
## Links         URLs, jira refs, sibling-brief map links
## Learnings     lessons, gotchas, dated changes

03Three scopes

Every fact belongs to exactly one scope. The scope decides which brief file it folds into.

global → compacted-shared.md project → compacted-<repo>.md topic → compacted-<slug>.md 
~/.aiforge/memory/
├─ compacted-shared.md          GLOBAL — cross-project truth (tooling, conventions, stack)
├─ compacted-oneshell-pos.md    PROJECT — one repo's classes/endpoints/bugs
├─ compacted-data-sync.md       TOPIC — a cross-cutting theme spanning repos
└─ okr/  global/ · projects/<repo>/   # the typed OKR-DAG (separate, deterministic)

06Compaction — the LLM fold

Facts accumulate in a brief's inbox; compaction re-folds them into clean OKR sections. One learner-LLM pass per brief.

consolidate() learner LLM, per brief
Dedupe paraphrases → one line · Supersede contradictions (archive the stale line, or keep it tagged [superseded]) · Map each item to its correct OKR section.
↓big input? chunk on structure (chonkie), fold chunk by chunk
deterministic fallback
model down → union + dedupe merge. Never raises, never loses a fact.
FULL RECOMPACT  — force_recompact_all, 10 steps (daily + on demand)
tidy_legacy → repo → topic → sweep → sweep_empty → dedupe
            → reheal (opt-in) → map_scopes → repo_profiles → reingest
reheal re-classifies each fact in every project brief and moves globals that slipped in over to the shared brief — the self-heal for "something mis-added." Heavy (one LLM call per fact), so opt-in.

07Links — mapping across scopes

Projects map to global, global maps back, topics link both — bidirectionally. Briefs are flat files, so a map link is a same-directory reference.

map_scopes() learner LLM
proposes which briefs share a specific subject at different scopes (a repo's branch rule ↔ the global branch convention). Strict — most briefs get no link.
↕writes the link into BOTH briefs
bidirectional sibling link
[global](compacted-shared.md) in the project brief, and the project link back in global. Fan-out capped; recomputed clean each run.

08Read path — gather, summarize, inject

Recall never dumps every snippet. It ranks across sources, and when a topic pulls a lot, folds them into one briefing first.

user turn query + repo scope
↓fan out
unified_query()
~10 sources in parallel (project brief, vector, graph hops, prior chats, tickets…), each scored, ranked + merged — repo-scoped so one project never bleeds into another.
↓many scattered hits?
summarize_hits() learner LLM
folds the ranked hits into ONE compact briefing — merge duplicates, drop the irrelevant. Below the threshold it keeps the raw ranked list.
↑inject into the system prompt
the agent arrives informed

Soft-fail is the contract everywhere: a model being down never breaks a chat turn or loses a fact — it degrades to the deterministic path and logs what it skipped.
